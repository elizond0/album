## 1. 架构

代码与内容清单在 GitHub Pages，照片/视频在 NAS；cloudflared 快速隧道把 `/srv/pub` 暴露为公网 HTTPS，页面靠 `base.json`（110 字节）找 NAS。

```
浏览器 → index.html（首页页脚可进 admin.html） / photos.html / timeline.html / quotes.html / wishes.html / videos.html / admin.html
   ├ data/content.json 内容源（文案 + 媒体相对路径 + 后台配置）
   ├ base.json         当前隧道地址（NAS 自动追平）
   └ scripts/site.js   渲染层，运行时把相对路径拼成绝对 URL
NAS album-node（Alpine + caddy + cloudflared）
   ├ /srv/csy           原图原片（共享文件夹 csy，只读；561 JPG + 16 MOV + 1 PNG = 578 项）
   │                    ※ /srv/photos 已废弃，不再挂载
   ├ /srv/pub           唯一发布目录：img/、img/t/、video/、video/poster/、index.json、base.json
   └ /var/lib/tailscale 脚本、Caddyfile、cf.log、.gh_token、orig_video/
```

`content.json` 只存 `img/xxx.jpg` 相对路径，地址在 `base.json`。

## 1.5 怎么连上 NAS（新对话第一件事，别问用户要密码）

凭据在云盘根目录《凭据》§B1，取用见《自制工具通用规则.md》§B7.4。

| 顺序 | 通道 | 判据 |
|---|---|---|
| 1 | **门户网页** `https://ug.link/<设备号>` → Playwright 打开 `/desktop/?os=ugospro#/` | `localStorage.proUserInfo` 的 `role=admin`、无密码框 |
| 2 | 上次留下的 `storage_state` 复用 | 同上 |
| 3 | 门户 → Docker → `album-node` → 终端（`.xterm-helper-textarea`） | 命令有回显 |
| 4 | SSH `22` | 绿联**默认不开**，`Connection refused` 是常态 |
| 5 | 公网 `9999` / `9443` | 多数只对内网开放，外网 `000` 正常 |

三条纪律：①网页终端单条命令超约 2000 字符**静默截断**，传文件用 1000 字符左右 base64 分段 `printf "%s" "..." >> /tmp/x.b64`，再 `base64 -d` 还原并 `sh -n` 校验，粘贴后必须 `grep` 回读确认；②写文件优先走接口：`POST /api/pull`（容器自拉最新脚本）、`POST /api/run`（只认 `nas-setup` / `pull` / `index` / `thumb`），都要口令（《凭据》§1.1）；③拉脚本 Pages 优先：`raw.githubusercontent.com` 实测 26 秒、`elizond0.github.io` 0.9 秒，容器内 `wget` 对 raw 常 `download timed out`。

## 1.6 验证码（TOTP）使用场景

**一句话**：全站只有**一把** TOTP 密钥，服务**四个**场景；换钥只需覆盖一个文件，四个场景同时生效。

| # | 场景 | 谁在用 | 入口 | 接口 | 认证要素 | 实测（2026-11-24 换钥后） |
|---|---|---|---|---|---|---|
| 1 | 相册门禁（看图 / 进站） | 自己、访客 | 任意前台页面的门禁浮层 | `POST /api/login` | 6 位动态码 / 恢复码 / 管理员口令 | 新码 → 200 `kind=totp`；旧码 → 401 |
| 2 | 相册后台登录 | 自己 | `admin.html` 解锁框 | `POST /api/auth` | 管理员口令 + 动态码（或门禁票直通） | 口令+新码 → 200 |
| 3 | 保存并发布 / 改动日志 | 自己 | 后台「保存并发布」、改动日志页 | `POST /api/save`、`GET /api/log` | **只要进门时验过的票**（`kind=totp｜admin`，12 小时）；票失效时**只补口令**，不再要动态码 | 带票 → 200；令牌失效→输入口令即 200 |
| 4 | 什么值得买 关注/屏蔽词表 | 自己 | smzdm 日报页的「关注/屏蔽」提交 | `POST /api/save-file` | 同上，走同一个 `_ok_admin()` | 带票 → 400「未知的词表类型」（**鉴权已过**）；无票 → 401 |

**密钥与副本的唯一性（换钥前必须确认）**

| 项 | 位置 | 含密钥？ | 说明 |
|---|---|---|---|
| 密钥（**唯一一份**） | 容器 `/var/lib/tailscale/totp-secret`（0600，32 字符 base32） | 是 | 换钥只动这里 |
| 恢复码（同批 8 个） | 容器 `/var/lib/tailscale/totp-recovery`（0600） | 否（一次性码） | `--set` 同时换新，旧的全部作废 |
| 代码：容器运行副本 | `/var/lib/tailscale/totp_auth.py`（10140 B） | 否 | `album-push.py` 同目录 `import totp_auth` |
| 代码：NAS 主副本 | 宿主 `/volume2/拓展工具/验证码/totp_auth.py` | 否 | 只放代码和文档，**不放密钥** |
| 代码：云盘 | `nas拓展工具/验证码/totp_auth.py` | 否 | 同上 |

- **只有一个进程读密钥**：`python3 album-push.py`（`ps -ef` 里除它之外没有第二个消费者；PDF 工具、Buddy 签到、青龙任务都不接 TOTP）。
- `totp_auth.secret()` **每次调用都重新读盘**，没有缓存 → **换钥后不用重启进程**。
- 自查命令（容器内）：`python3 totp_auth.py --check` 应回 `totp: 开 | 恢复码: 8 个 | 目录: /var/lib/tailscale`。

## 1.7 退出与清票（自测验证码必用）

**为什么必须有这个按钮**：门禁票签发后 **12 小时有效，且存在浏览器 localStorage 里**。换 TOTP 密钥、换管理员口令都不会让已发出的票失效（只有 `--set-key` 会顺手吊销管理员票）。所以「改完验证码想测一下」时，不清票就会一直拿旧票直通，看着像新码根本没生效——这是最容易误判的一种。

**两处入口**

| 位置 | 形态 | 覆盖范围 | 说明 |
|---|---|---|---|
| 页面右下角 | 胶囊按钮「退出」，`position:fixed` 14px，约 60×33 px，平时 `opacity:.72`、悬停变实 | **全部 6 个前台页**（首页 / 时间轴 / 照片墙 / 随手记 / 心愿单 / 影像） | 由 `scripts/gate.js` 统一注入，只有**持票时**才出现；没票不显示（没票也没什么可退） |
| 页脚 | 文字链接「退出」 | 6 个前台页都有 | 首页页脚是「管理后台 · 退出」；子页只有「退出」 |
| `admin.html` | 导航栏「退出管理」（原有） | 后台 | 后台页**不再**注入浮动按钮，避免一页两个退出 |

**退出到底清了什么**

| 键 | 存哪 | 清？ | 说明 |
|---|---|---|---|
| `album_gate_v1` | localStorage | ✅ | 门禁票，主力 |
| `album-admin-token` | sessionStorage | ✅ | 后台一次性令牌 |
| `album-gp` | sessionStorage | ✅ | 动态码过关凭证（`proof`），不清会让人「退了还能免码发布」 |
| `album-admin-hash` / `album-admin-key` | 两处 | ✅ | 旧版遗留键，留着会出现「页脚退了、后台还登录着」的鬼影 |
| `album-admin-totp` | localStorage | ❌ 保留 | 只是「后台已开动态码」的 UI 记忆，不是票，清掉反而要重新勾一次 |
| 其它站点的键 | — | ❌ 不动 | 只清 `album-` / `album_` 前缀，同域下值得买、PDF 工具站不受牵连 |

**跳转方式**：`location.replace(pathname + "?out=" + Date.now())`。带时间戳是为绕过 `index.html` 的 HTTP 缓存，用 `replace` 是为让后退键回不到已解锁的页面快照。地址栏里的 `?out=` 由 `gate.js` 自己用 `history.replaceState` 抹掉，不会留在书签里。

**什么时候用它**

1. 换钥 / 改管理员口令后，验「新码能进、旧码 401」；
2. 想从管理员身份切到访客身份试权限（虽然 `--no-guest` 后没有访客入口了）；
3. 把设备借出去、或在公共电脑上用完；
4. 图片整片裂掉（票还在但服务端已吊销）时，退出重验就是最快的修复。

> 自测动作固定成两步：**点「退出」→ 回到输码页 → 输新码**。如果退出后还直通，说明有别的标签页或别的浏览器配置还在带票，不是服务端问题。

## 1.8 一次验证，够用 12 小时（发布不再二次要码）

**规矩**：进门那一关验过（口令+动态码，或用动态码换的门禁票直通），拿到的令牌 **12 小时内**覆盖所有后台写操作——保存并发布、改动日志都直接放行，**不再出现第二个动态码框**。

| 情形 | 以前 | 现在 |
|---|---|---|
| 刚进门就发布 | 令牌直通 | 令牌直通（不变） |
| 令牌没失效 | 直通 | 直通（不变） |
| 令牌失效（超 12 小时 / NAS 重启过） | 弹框**同时要口令和动态码** | 弹框**只要口令**，输完即发 |
| 改动日志读不到 | 提示「刷新页面重新进后台」 | 提示「点右上角「退出管理」重新进一次」（刷页面没用，票在 sessionStorage 里会保留） |

**为什么可以不要第二次动态码**：动态码这一道挡的是「口令泄露后随手改内容」。进门时已经卡过一次，而令牌是服务端内存里的一次性随机串、只在当前标签页的 sessionStorage 里，比口令本身更难拿。若令牌真失效，说明服务端已经不认这张票，此时再要口令就够——再要一次动态码只是让人在 1 小时内输两遍同一个东西。

**⚠ 关键实现：`proof` 凭证（v1.25）**

「只输口令」这句话单说是不成立的——服务端 `/api/auth` 只要开了动态码就必须验码，光有口令换不到令牌。中间靠一张短效签兜住：

| 环节 | 做了什么 |
|---|---|
| 签发 | `/api/login`（门禁）或 `/api/auth` 验过动态码/恢复码/管理员口令后，响应里多一个 `proof`。**访客票不发** |
| 存放 | 前端存 `sessionStorage["album-gp"]`。session 级，关标签页即消失；「退出」按钮也清它 |
| 使用 | 后台票失效时，`nasPush()` 只弹口令框，提交 `{key, proof}`；服务端认签 → 发新令牌 + 换一张新签 |
| 格式 | `base64url({"e": 过期毫秒}) + "." + hmac_sha256(密钥, 前半段)`，TTL 12 小时，纯自证、不落盘不进内存 |
| 吊销 | 签名密钥由 `push-secret` 派生，**`--set-key` 换口令 = 当场作废全部旧签** |

所以发布时的安全边界是：**口令（你知道）+ 12 小时内验过码的凭证（这个浏览器有）**。少任一样都发不出去——实测「清掉 proof 只输口令」→ `401`，反证这张签不是摆设。

**代价（如实记）**：令牌有效期内，浏览器若被他人接管，可直接发布。缓解手段是「退出管理」或右下角「退出」（两个都会清令牌与 `album-gp`），以及 `--set-key` 换口令会**当场吊销全部旧票与旧签**。

**没变的部分**：`X-Admin-Key` + `X-Admin-Code` 这条老通道在服务端仍然保留（`_ok_admin()` 第三段），给运维脚本用；只要走它、且开了动态码，服务端照样校验动态码。本次改的只是**后台页面不再主动走这条路**。

## 3. 日常：加照片 / 加视频

文件丢进 `共享文件夹/csy/`（容器内 `/srv/csy`，**只读挂载**），然后容器终端跑 **2.6 那条命令**，再跑 **2.7 重建清单**。不重启容器、不改地址、不碰 GitHub。

只读两个预期行为（非故障）：①第 2 步「统一小写」自动跳过（ro 上 `rename` 会 EROFS）；②第 0 步先数源里媒体文件，**为 0 或不到已发布数一半即退出**（防挂错目录）。

处理规则（顺序错就是错）：

| 环节 | 规则 |
|---|---|
| 图片压缩 | 读 EXIF 日期 → `exif_transpose` 烘焙方向 → 转 RGB → 长边 **2048** LANCZOS → JPEG **q85 + optimize + progressive**，不写 EXIF/ICC → 文件名小写 |
| 缩略图 | 长边 **720**、q78、progressive，只给网格用；灯箱取 2048 |
| 视频转码 | H.264 / `yuv420p` / `+faststart` / 去 metadata / 长边 ≤1280 / `force_divisible_by=2` |
| 视频封面 | `ffmpeg -ss 1 -frames:v 1` → `video/poster/<同名>.jpg`，`mkindex.py` 写成 `p` 字段 |
| 文件名 | 原图、压缩图、视频、封面、`seed.json`、`content.json` 一律小写 |

#### 3.3.1 版本时间戳（v1.16）

页脚 `[data-stamp]`（`2026.11.23 17:04`）与后台最底部 `#admin-stamp` 同值，都由 `builtAt` 驱动：`admin.js` 保存时写 `YYYY-MM-DD HH:mm`（本地时间，精确到分）；`site.js` 的 `Site.stampText()` 统一格式化（兼容纯日期 / 日期+时分 / ISO 旧值），`Site.renderStamp()` 刷 `[data-stamp]`；后台调同一函数；发布成功即刷新后台页脚。

#### 3.3.2 改动日志（v1.16）

- **写**：`album-push.py` 提交成功后结构化对比新旧 `content.json`，append 一行到 `/var/lib/tailscale/changes.jsonl`（`{t, commit, photos, builtAt, by, ip, size, changes[]}`），留 200 条。
- **读**：`GET /api/log?limit=30`，须带后台身份（`X-Admin-Auth`，或 `X-Admin-Key` + `X-Admin-Code`），否则 401。

#### 3.3.3 照片墙「行数」只有一个数（v1.16）

#### 3.3.4 灯箱到边即停（v1.17）

旧 `Site.lightbox.step()` 取模 `idx = (idx + d + n) % n`，末张再往后绕回首张 → 现 `idx + d` 越界即 `return`；`syncNav()` 在 `fill()` 末尾跑，首张 `prev.disabled`、末张 `next.disabled`（CSS `.lightbox__btn[disabled]{opacity:.22;pointer-events:none}`）；键盘/滑动同走 `step()`。范围收窄：首页 `renderPhotosPaged()` 维护 `seen` 活数组，灯箱只在此数组内翻；子页传 `list.slice(start, start+count)`，翻到末张即停。

## 5. 按症状查

| 症状 | 根因 → 做法 |
|---|---|
| 子页面全部 404 | 站内链接写成 `/photos.html`；站点在 `/album/` 子目录、绝对路径解析到域名根 → 用同层相对路径 |
| 首页打开就下载几十 MB | `<video>` 为 `preload="metadata"` 且无 poster，Chromium 发 `Range: bytes=0-` 拖整段 mp4 → `preload="none"` + poster |
| 图片全破图 / 一张都不出来 | `base.json` 域名死了；或 Caddy 缺 `Access-Control-Allow-Origin "*"` |
| 手机验证器的码总被拒 | **不是服务端 bug**。`totp-secret` 只认最后写入的那把密钥；历史上跑过 `--set`（或在「验证码工具」里重新生成）就会换钥，手机里那条旧记录随之失效。核对：NAS 上 `python3 totp_auth.py --show` 看服务端当前码，与手机对比；不一致就在手机里删掉旧条目，重新扫 `--set` 打印的二维码（`otpauth://totp/homelab:totp-auth?...`）。密钥文件路径与指纹见 §1.2 与《凭据》§1.2。**换钥后恢复码也一并换新**，旧恢复码作废 |
| 地址变了页面还是旧的 | `base-sync.sh` 没在跑（`ps \| grep base-sync`）；或 `index.json` 被缓存（须 `no-store`） |
| 转码卡住、进程在但 CPU 0 | 后台脚本连着终端 pty，ffmpeg 读 stdin 吃 `SIGTTIN` → `exec </dev/null` |
| 新增照片不出现 | 只跑了缩略图、没跑 `pub_img.py` → 现由 `nas-setup.sh` 第 3 步统一处理 |
| 每次跑都重转全部视频 | 判成品只看体积、`video/` 空掉就判待转码 → 只看**封面在不在**（`video/poster/<名>.jpg`，转码成功才生成） |
| 改了 `nas-setup.sh` 容器里没变 | 容器不跟仓库同步 → `POST /api/pull` 或 `_pull.sh`；`wget` 超时换 Pages |
| 脚本「跑成功」但新照片没上线 | 源目录挂错 → 看第 0 步「媒体文件 N 个」，N=0 或远小于已发布数即挂错 |
| 日志里 563 张、别处 562 张 | `ls img \| wc -l` 把子目录 `t` 算一条 → 写 `ls img/*.jpg \| wc -l` |
| 站点少一张历史照片 | `pub_img.py` 按源重建清单、源里已删的会掉 → 默认孤儿保留补回（`--skip-existing`），`orphan` 计数应 > 0 |
| 子页标题「我们的故事 · 我们的故事」 | `meta.texts.siteShort` 丢了 → `build_content.py` 的 `CARRY_KEYS` 要含 `texts` / `pages` |

| 视频在 Chrome 播不了 | MOV 里装 HEVC，`-c copy` 改封装没用 → 必须真转 H.264 |
| 首页照片墙只有 2 排（第一层） | `renderPhotosPaged` 只靠 `IntersectionObserver` 入场回调补页，首屏元素在视口附近时未必回调 → `sync()` 后主动补页 |
